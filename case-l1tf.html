Foreshadow / L1 Terminal Fault

Translation fails, yet data associated with the invalid entry may be transiently supplied from L1D.

First understand the mechanism

Trigger
Terminal address-translation fault
Data / prediction source
Relevant data already in L1D
Architectural result
Page fault; no valid translation
Affected transient behavior
L1D value forwarded despite failure

An invalid page-table entry can still contain physical-address bits. On affected implementations a terminal fault may not stop those bits from participating in transient access to an already resident L1 data-cache line. The teaching value 0x2A is that line’s existing data, not a virtual address or an attack parameter. A missing L1D line does not turn this into an unrestricted DRAM read.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] request: LOAD(V)
[02] translate(V) = INVALID
[03] setup: relevant L1D line contains 0x2A
[04] transient possibility: t = 0x2A; dependent_use(t)
[05] architectural: report page fault
[06] control: no relevant L1D residency → this source absent

Compare [02] with [04]: the request has no valid translation, yet the possible value is limited by [03]. The value 0x2A is cached data, not a PTE or an address. The control in [06] removes this particular data source.

What is trained or triggered?

No branch training. Track both constraints: an applicable invalid translation and relevant L1D residency. Unlike the classic Meltdown example, the translation itself is invalid rather than a valid supervisor-only mapping.

Prerequisites and trust boundary

Foreshadow studied SGX; related L1TF variants cover OS/SMM and virtualization boundaries. Their CVEs and attacker control differ. An untrusted host manipulating an enclave’s environment is a different threat model from a normal unprivileged process.

What does the mitigation interrupt?

PTE inversion prevents invalid entries from naming cacheable physical memory. Relevant VM-entry L1D flushing and SMT scheduling/isolation address other parts of the chain. Flushing one boundary does not automatically stop simultaneous activity on a sibling thread.

Do not confuse these concepts

L1TF selects through invalid translation and L1D residency. MDS samples internal buffers and generally cannot choose a secret address in this way.
