04 / DEFENSE & SOURCES

Mitigations span layers;
so must the conclusions

Software gadgets, compilers, kernels, microcode, firmware, isolation and scheduling can each handle different aspects. Confirm trust boundaries and machine status before deciding priorities.

Mitigation LayersAudit ChecklistRead-Only Status CheckTEE/Cross-ArchitectureFirst-hand information
01 / DEFENSE IN DEPTH

Each layer addresses a different problem

There is no universal switch that eliminates all side channels. Mitigation may also come with a performance cost that must be evaluated against a realistic threat model.

SOURCE / COMPILER

Reduce exploitable gadgets

Use vetted constant-time implementations on sensitive accesses; use appropriate index constraints, barriers, or compiler hardening for specific predictive gadgets. Ordinary bounds checking cannot guarantee transient safety.

Intel cryptography Implementation Guide ↗
KERNEL / RUNTIME

Isolation and entry paths

The kernel and runtime may use KPTI, retpoline, IBRS/IBPB, STIBP, SSBD, BHI special mitigation, etc.; their applicable attack categories and cross-domain boundaries are different.

Linux Spectre Documentation ↗
MICROCODE / PLATFORM

Processor-specific mitigations

MDS/GDS buffer cleaning, predictor control, hardware revision, etc. need to be checked against the firmware version according to the manufacturer's announcement; the virtual machine also depends on the host layer.

Intel Mitigation Overview ↗
"Enable Mitigation" is a statement for a specific issue, model, and trust boundary. Don't read a system status string as "no more side channels for the entire CPU".
02 / REVIEW CARD

A one-page review checklist

Used for system design review, cryptographic implementation review or cloud deployment inventory; the conclusion should record the source and date of the evidence.

THREAT

Who shares resources with whom?

What are the respective permissions and sharing conditions for untrusted local code, browser scripts, same-core SMT threads, other VMs, hosts, and TEE external code?

SECRET

Where is the secret?

Keys, session materials, protected pages, registers, internal buffers. Do critical operations rely on secrets to change access patterns or duration?

MACHINE

What is this machine’s current state?

Record CPU model/stepping, microcode, BIOS, kernel, virtualization layer, SMT, compiler and mitigation status, not just a list of CVEs.

EVIDENCE

What level of evidence do we have?

Theoretical possibilities, laboratory PoC, affected product announcements, system mitigation displays, and production monitoring events cannot replace each other.

CHANGE

What will an update change?

Upgrade CPU microcode and OS; check performance and compatibility; re-read official announcements and system status, and review regularly.

RESIDUAL

What residual risk remains?

Software timing leaks, new variants not covered, TEE shared microarchitecture state, host invisible mitigation and multi-tenant scheduling.

03 / READ-ONLY CHECK

Check Linux mitigation status first

The following command only reads the vulnerability status exposed by the kernel and does not modify the mitigation settings. The output may vary between distributions and virtual environments.

uname -a grep -m1 -E 'model name|Hardware' /proc/cpuinfo for file in /sys/devices/system/cpu/vulnerabilities/*; do printf '%s: ' "${file##*/}" cat "$file" done
If you see "Not affected" or "Mitigation" in the VM, you should also consider the host CPU, hypervisor exposed features and vendor announcements. If "Unknown" is output, do not interpret it as "safe". See Linux Hardware Vulnerability Index ↗.
04 / TRUSTED EXECUTION

TEEs also run on real CPUs

Encryption and isolation protect defined interface and architectural boundaries; they do not automatically eliminate all shared microarchitecture state.

SGX

Foreshadow and SGXSpectre

Two types of research respectively demonstrate the different threats of L1TF and predictive gadgets to enclave. When reading the paper, distinguish between the SGX key/page content and the leakage target of the experimental demonstration.

Inspect the host–guest boundary
