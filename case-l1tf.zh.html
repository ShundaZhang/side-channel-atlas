Foreshadow / L1 Terminal Fault

地址翻译失败，但与无效页表项相关的数据可能仍从 L1D 被瞬态提供。

先理解机制

触发事件
终止性地址翻译故障
数据 / 预测来源
相关数据已驻留 L1D
正式结果
页故障，没有有效翻译
受影响的瞬态行为
失败后仍可能转发 L1D 值

无效页表项仍可能含有物理地址位。在受影响实现中，终止性故障未能阻止这些位参与对已驻留 L1 数据缓存行的瞬态访问。教学值 0x2A 是该行原有数据，不是虚拟地址或攻击参数。若相关数据不在 L1D，也不能据此把机制延伸成任意 DRAM 读取。

语义伪代码 / 不是可执行 PoC

01  request = LOAD(V)  // 请求的是地址，不是缓存索引
02  translate(V) = INVALID  // 发生终止性地址翻译故障
03  relevant_L1D_line = 0x2A  // 教学设定的驻留字节
04  transient: t = 0x2A; dependent_use(t)  // 翻译失败后仍发生受影响的转发
05  architectural: page_fault()  // 不提交有效翻译或该读取值
06  control: evicted line => source absent  // 不能由此推导为任意 DRAM 读取

跟着教学例子走一遍

编号语义伪代码，不是可运行攻击。标签和数值均为教学设定，不配置预测器、不制造故障，也不解码秘密。图是概念模型，不是实测时序。
[01] 请求：LOAD(V)
[02] translate(V) = INVALID
[03] 教学设定：相关 L1D 行含有 0x2A
[04] 可能的瞬态过程：t = 0x2A，依赖操作使用 t
[05] 正式：报告页故障
[06] 对照：相关数据不驻留 L1D，则缺少这条来源

对照 [02]、[04]：请求没有有效翻译，但可能出现的值受 [03] 限制。0x2A 是缓存数据，不是 PTE 或地址。[06] 的对照移除了这一特定来源。

训练 / 输入到底是什么

不训练分支。要同时跟踪可利用的无效翻译与对应 L1D 驻留。它与经典 Meltdown 示例不同，后者通常是有效但仅主管可访问的映射。

成立前提与信任边界

Foreshadow 原研究面向 SGX；相关 L1TF 变体涉及 OS/SMM 及虚拟化边界，CVE 与攻击者控制能力不同。不可信宿主操纵 enclave 环境，与普通非特权进程的威胁模型不同。

缓解切断了哪一环

PTE inversion 使无效项不再指向可缓存物理内存。相关 VM 入口 L1D 刷新、SMT 调度 / 隔离则处理攻击链的其他环节。在一个边界刷新缓存，不自动覆盖兄弟线程的并行活动。

容易混淆的概念

L1TF 的核心约束是无效翻译与 L1D 驻留。MDS 面向内部缓冲区采样，通常不能以同样方式指定秘密地址。
