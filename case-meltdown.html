Meltdown V3 · Rogue Data Cache Load

A load still faults, but affected hardware may already have forwarded the protected byte to dependent transient instructions.

First understand the mechanism

Trigger
Load lacks user permission
Data / prediction source
Data behind a protected mapping
Architectural result
Permission page fault; no byte committed
Affected transient behavior
Dependent operation uses the byte

First separate two examples. An independent operation below a faulting instruction can execute early without consuming the fault’s result. Classic Meltdown’s disclosure chain is stronger: it needs a dependent operation to receive the byte from the denied load. A later architectural exception does not prove that permission checking itself waited until retirement; check failure, blocking data forwarding and reporting a fault are distinct events.

Line [03] depends on the byte requested in [02]. An independent access merely placed after a faulting instruction demonstrates a different, weaker property. Line [05] is separate ordinary observation after a suitable recovery path, not continuation of the forbidden load.

What is trained or triggered?

No branch training is required for the core mechanism. The teaching setup is a mapped page that user mode may not read, on a vulnerable implementation. A valid but forbidden mapping and an absent mapping are different cases.

Prerequisites and trust boundary

The classic case concerns user/kernel isolation. The exact reachable data depends on mappings, hardware behavior and system configuration. A failed PoC on patched hardware says nothing by itself about an unrelated Spectre or sampling mechanism.

What does the mitigation interrupt?

PTI/KPTI removes most kernel mappings from the user page-table view and switches page tables at kernel entry/exit. This removes a prerequisite; it is not a branch-predictor flush and is not a general fix for all transient execution.

Do not confuse these concepts

The later timing measurement is ordinary observation code, not execution resuming at the original next instruction after the fault handler. The transient byte is never a permitted architectural read.
