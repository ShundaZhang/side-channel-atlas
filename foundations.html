01 / COMMIT

Architectural state is not all CPU state

The registers, memory, exceptions and control flow that programmers can observe from the ISA belong to the architectural state. The out-of-order core also maintains caches, branch predictors, reorder buffers (ROB), load/store queues, etc. After an incorrect prediction is discovered, uncommitted instruction results will be discarded; however, traces such as cache lines loaded during execution may not automatically return to their previous state.

So "not submitted" does not mean "not executed". This difference is the starting point for understanding transient execution attacks and alsoIntel Terminology DocumentContext that distinguishes disclosure gadgets from channels.

Architectural

The register writes and exception handling results of the wrong path will not be visible to the program like normal committed instructions.

microarchitecture on

The cache, predictor, or temporary buffer may have changed; the attacker then observes indirectly from the difference in elapsed time.

Inside an out-of-order core

The ISA defines the software-visible contract: instructions, registers, exception rules, privilege levels and memory ordering. A microarchitecture is a concrete implementation of that contract. Two processors running the same binary can differ in cache geometry, predictor design, instruction throughput, timing and speculative behavior. Architectural memory rules still apply even when internal execution proceeds in a different order.

02 / OBSERVATION

A side channel is statistical inference, not direct memory access

Observers cannot read the secret through the normal interface, but can see the phenomena affected by the secret: execution time, cache contention, power consumption, frequency, port occupancy or memory access pattern.Side channelUsually emphasizes inferring information from victim activities;Covert channelUsually emphasizes the sender actively encoding data into unintended shared resources. In a transient execution attack, the attacker may induce the victim to transiently encode the secret and then receive it himself.

The actual measurement is not fixed like "60 cycles for a hit and 200 cycles for a miss". Core frequency, prefetchers, interrupts, core migration, timer precision, and competing tasks can all cause overlapping distributions. When reading the paper, you should look for the number of samples, success rate, bandwidth, false alarm rate and hardware configuration, rather than just watching the demonstration video.

secret → shared microarchitectural state → timing distribution → inference
Timing side channels, cache side channels, and power/frequency side channels do not all rely on transient execution; in turn, transient execution also requires an observable leak channel to cause information leakage.

03 / CACHE PRIMITIVES

Two ways to observe a cache trace

A cache transfers memory in lines. In a conventional set-associative cache, an address maps to a set; a tag identifies the line among the W ways. For a simple power-of-two cache, the low log₂(line size) bits are the byte offset, the next log₂(set count) bits select the set, and the remaining high bits form the tag. Real LLCs can also hash physical address bits to select a slice or bank. Virtual addresses alone do not in general reveal all these bits.

Flush+Reload

Observe one shared physical line. A faster reload suggests a recent access to that line.

Prime+Probe

Observe contention in one set using your own lines. A slower probe suggests displacement.

Flush+Reload

Choose an address whose line aliases the same physical bytes in both processes, such as read-only code from a shared file mapping. Virtual addresses can differ. A private copy created by copy-on-write breaks that alias. On suitable x86 systems CLFLUSH invalidates the line from the coherence domain. Check instruction support, ordering, mapping and actual cross-core behavior on the measurement platform.

for each window:
    invalidate L and order before the window
    wait for the observation interval
    dt = time_first_load(L)
    record(timestamp, dt, dt < threshold)

Label baseline samples using a controlled reader: touch versus no touch. A prefetched or unrelated access is a false positive; eviction before reload, a missed window or a delayed measurement can give a false negative. A fast reload can involve a private cache, LLC or cache-to-cache transfer. Measure class distributions rather than assigning a cache level from a single time. The original study demonstrated a high-resolution shared-line probe under its platform assumptions.

Yarom and Falkner · USENIX Security 2014 ↗

Prime+Probe

For an LLC example, select attacker-owned addresses that compete in the same set and slice, then validate that accesses to them evict a reference line. They need not share physical pages with the victim. The cache must be shared at the chosen level, and a victim access must actually reach or affect that level. A private-cache hit can leave little LLC signal on some designs.

  1. Prime: traverse A in a validated order. A dependent pointer chain makes later loads wait for earlier ones, reducing overlap and simple stride prefetching.
  2. Wait: allow one interval for the victim. A conflicting line can replace an A line; interrupts and other tasks can do the same.
  3. Probe: time either the full traversal or per-line reads. Keep the order stable; one reload can itself displace another attacker line.
  4. Infer: compare slow probes or miss counts to an idle baseline. The result identifies a contested set within the window. Many unrelated lines map there.
A = validated_congruent_lines(set, slice)
for each window:

How an eviction set is found

Start with a pool S of owned addresses and a reference x. Similar page offsets can constrain some set-index bits; unknown physical bits and the slice hash remain. Define an oracle: warm x → traverse S → time x. Repeat and check the eviction rate against positive and negative controls. Keep a reduced pool only if it still evicts x reliably. Finally test the resulting set across fresh runs and access orders.

A greedy reduction tries removing one address at a time. Vila et al. use group elimination: in the ideal W-way model, split a large pool into W+1 groups. If at least W congruent lines suffice and only W of them are needed, at least one group can be removed while keeping those W. Test group complements, recurse, then verify individual members. This ideal monotone oracle can break in real runs because of TLB thrashing, cache policies and sampling noise. Track a measured eviction rate with uncertainty.

Other probes and trade-offs

Evict+Reload replaces explicit flush with a congruent eviction set and still times the target line. Flush+Flush times the flush instruction itself, whose latency can depend on residency on the studied CPU. The NDSS 2025 comparison also evaluates demotion-based probes on specific processors. Check each paper’s shared-memory assumption, observation direction, temporal resolution, and false-positive rate.

04 / TRANSIENT WINDOW

Several ways to trigger transient execution

Predictive type:Training conditional branches, indirect branches, or return predictions causes the processor to temporarily follow the wrong path. Spectre V1 is bounds check bypass; V2 is indirect branch target injection. The wrong path is revoked, but the cache encoding can be left.

Faulty/Assistant:Error values ​​may enter the transient dependency chain before permission checks, page faults, or microcode assistance complete. The original Meltdown (Variant 3) falls into this category. It cannot be assumed that all CPUs have the same data forwarding behavior.

Data sampling type:The internal buffer and vector register related structures of a specific processor may allow expired data to enter transient instructions. The objects of MDS and GDS are more like "some data near the same core", which is not equivalent to reading at any address.

It is useful to treat Spectre and Meltdown as two historical entries, but subsequent variants cannot be classified by name alone; look at the specific prediction/forwarding mechanism, crossed boundaries, and list of affected vendors.Intel's classification recommendationsalso emphasize this point.

Out-of-order execution schedules ready work early. Speculation additionally assumes a result or path before it is resolved. Fault-driven transient work can arise without a branch misprediction. The useful window is bounded by dependency latency, the front end, queue capacity and when recovery starts. A delayed branch operand can open time for a dependent load, while a second miss on the wrong path can consume the entire window.

05 / ANATOMY

Trace the logic of a Spectre V1 attack

The victim will normally check the index and then access the array. The attacker provides input and influences the predictor. If the processor temporarily guesses "check passed", the wrong path may read an out-of-bounds position; if its value is used as an index into another probe array, it will make a certain cache line hot. The processor eventually discovers that the check failed and revokes the architectural result; the attacker can still test which probe line is faster. The demonstration in the original paper relied on repeated training, measurement and noise reduction, and one timing cannot be regarded as a reliable leak.

train → mistrain → transient load → encode(value) → squash → time(probe)

Here "crossing the boundary" refers to the software object/sandbox boundary, which does not mean arbitrarily reading another process or kernel address. V2, Meltdown, MDS have different triggers and boundaries. Read againstoriginal Spectre paperandoriginal Meltdown paper.

06 / THREAT MODEL

Do not infer platform security from one PoC result

  • Attacker capabilities:Can it run native code, JavaScript, same-core threads, or a malicious VM?
  • Target secret:Same process, cross-process, kernel, virtual machine, SGX/TEE, different boundaries.
  • Hardware conditions:Microarchitecture intergenerational, SMT, TSX, cache sharing, predictor isolation will change the effect.
  • Software conditions:Microcode, kernel, browser, compiler, virtualization layer and related switches must be recorded.
  • Level of evidence:Thesis concept, controlled PoC, vendor announcement, and exploitation in the wild are different claims.
