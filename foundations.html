01 / COMMIT

架构状态不等于 CPU 的全部状态

程序员能从 ISA 观察到的寄存器、内存、异常和控制流属于架构状态。乱序核还维护缓存、分支预测器、重排序缓冲区（ROB）、载入 / 存储队列等。错误预测发现后，尚未提交的指令结果会被丢弃；但执行过程中加载的缓存行等痕迹，未必自动恢复到此前状态。

所以“未提交”不意味着“未执行”。这个差别是理解瞬态执行攻击的起点，也是Intel 术语文档区分 disclosure gadget 与通道的背景。

架构上

错误路径的寄存器写入和异常处理结果不会像普通已提交指令一样对程序可见。

微架构上

缓存、预测器或临时缓冲区可能已经变化；攻击者随后从耗时差异间接观察。

02 / OBSERVATION

侧信道是统计推断，不是“直接读内存”

观察者不能通过正常接口读取秘密，却能看见受秘密影响的现象：执行时间、缓存竞争、功耗、频率、端口占用或内存访问模式。侧信道通常强调从受害者活动推断信息；隐蔽信道通常强调发送端主动把数据编码进非预期共享资源。瞬态执行攻击中，攻击者可能诱导受害者瞬态编码秘密，再自行接收。

实际测量不是“一次命中 60 周期、未命中 200 周期”这样固定。核心频率、预取器、中断、迁核、计时器精度和竞争任务都会使分布重叠。读论文时应找样本数、成功率、带宽、误报率及硬件配置，而不只看演示视频。

secret → shared microarchitectural state → timing distribution → inference
计时侧信道、缓存侧信道、电力/频率侧信道并不都依赖瞬态执行；反过来，瞬态执行也需要一个可观测的泄漏通道才能形成信息泄露。
03 / CACHE PRIMITIVES

Flush+Reload 与 Prime+Probe 测的不是同一条件

Flush+Reload

攻击者能访问与受害者共享的同一物理缓存行时，先逐出（Flush），让受害者运行，再测重载（Reload）耗时。若重载偏快，表示那条缓存行可能被触碰过。它通常给出细粒度信号，但共享页面 / 内存映射是重要前提。

Prime+Probe

攻击者先占据目标缓存组（Prime），让受害者运行，再观察自己的缓存行是否被逐出（Probe）。它关注缓存组争用，未必要求双方共享具体页面，但构造逐出集合、处理地址映射与噪声更难。

还有哪些？

Flush+Flush 测 flush 本身的时间；Evict+Reload 用逐出集合替代显式 flush；端口竞争、TLB、预测器、频率等构成其他观察面。名称不同，不代表都能越过同一安全边界。可从MIT Secure Hardware Design 教学实验与 Transient Fail PoC 集对照这些条件。

Flush+Reload：同一行

共享物理内存往往是关键前提；问“攻击者如何得到同一行”。

Prime+Probe：同一组

依赖争用关系；问“缓存索引与逐出集合如何确定”。

04 / TRANSIENT WINDOW

触发瞬态执行的几条路

预测型：训练条件分支、间接分支或返回预测，使处理器暂时沿错误路径执行。Spectre V1 是边界检查绕过；V2 是间接分支目标注入。错路径被撤销，但可留下缓存编码。

故障 / 辅助型：权限检查、页故障或微码辅助完成前，错误值可能进入瞬态依赖链。原始 Meltdown（Variant 3）属于此类。不能假定所有 CPU 都有同样数据转发行为。

数据采样型：特定处理器的内部缓冲区、向量寄存器相关结构可能让过期数据进入瞬态指令。MDS 与 GDS 的对象更像“同核附近的某些数据”，不等同于按任意地址读取。

把 Spectre 与 Meltdown 当作两个历史入口有用，但后续变体不能只靠名字分类；看具体的预测 / 转发机制、越过的边界和厂商受影响清单。Intel 的分类建议也强调这一点。

05 / ANATOMY

拆解一次 Spectre V1 的逻辑链

受害者正常会检查索引，再访问数组。攻击者提供输入并影响预测器。若处理器暂时猜“检查通过”，错路径可能读取越界位置；其值若又用作另一块探针数组的索引，就会把某一条缓存行变热。处理器最终发现检查失败，撤销架构结果；攻击者仍可测哪条探针线更快。原始论文中的演示要靠反复训练、测量和降噪，不能把一次计时当作可靠泄漏。

train → mistrain → transient load → encode(value) → squash → time(probe)

这里“越界”指软件对象 / 沙箱边界，不等于任意读取另一个进程或内核地址。V2、Meltdown、MDS 的触发和边界各不相同。对照原始 Spectre 论文和原始 Meltdown 论文阅读。

06 / THREAT MODEL

不要从 PoC 成败直接推断平台安全

  • 攻击者能力：能否运行本地代码、JavaScript、同核线程或恶意 VM？
  • 目标秘密：同进程、跨进程、内核、虚拟机、SGX / TEE，边界不同。
  • 硬件条件：微架构代际、SMT、TSX、缓存共享、预测器隔离会改变效果。
  • 软件条件：微码、内核、浏览器、编译器、虚拟化层和相关开关都要记录。
  • 证据级别：论文概念、受控 PoC、供应商公告、在野利用是不同的主张。
