01 / SIMULATOR

缓存命中，为什么不能凭一次计时判断？

这是带可调噪声的教学模型，数字不代表任何真实 CPU 的周期数。观察分布如何重叠、判决如何出错。

Hit / Miss 计时模型

每类生成固定 100 个样本。改变“噪声”和阈值，观察判决准确率。

样本分布 · Hit / Miss（从左到右耗时增加）

你应该看到什么

噪声上升时两组样本重叠，判决准确率下降。把阈值偏向一侧，会增加某一类的误判。

真实实验需要控制线程位置、预热、计时器、预取效应并统计重复试验。机器报告中的“脆弱 / 已缓解”不能由这个动画推断。

这个模型没有真实 flush、分支预测或秘密读取，只用于解释为什么论文报告多次采样、错误率与信噪比。

02 / SIMULATOR

回滚为何仍可能泄漏？

逐步推进一个简化的 Spectre V1 故事。所有值都是页面内的教学常量。

0 / 攻击者训练：检查通常通过
1 / CPU 暂时预测：本次也通过
2 / 错路径：读取 toy secret = 3，触碰 probe[3]
3 / 检查失败：撤销错路径架构结果
4 / 测量：probe[3] 在模型里仍为热

模型特意省略了什么？

真实核的 ROB、load 依赖、分支预测器、缓存层级、故障处理，以及需要大量重复测量的噪声。页面绝不尝试触发本机 Spectre。

这个模型只解释“架构回滚”和“微架构痕迹”可以并存。返回完整攻击链 ↗

03 / LOCAL BASELINE

测一次自己的缓存行

仓库提供最小 x86-64 教学程序，仅对进程自有缓冲区比较 cached 与 flushed 的访问时间，不跨越权限边界。

运行方式（x86-64 Linux / macOS）

git clone https://github.com/ShundaZhang/side-channel-atlas.git cd side-channel-atlas cc -O2 -Wall -Wextra examples/cache_timing.c -o cache_timing ./cache_timing ./cache_timing --csv > timings.csv

在原生 x86-64 上运行，需支持 CLFLUSH 和 RDTSCP。默认输出以 TSC 刻度报告中位数；CSV 保留热读／逐出后读的采集顺序。固定配对顺序适合观察基线，更严格的比较需在独立运行中随机排列条件。 cache_timing.c ↗

实验记录模板

记下 CPU 型号、操作系统、编译器、是否虚拟化、hit / miss 中位数、样本数，以及“观察到 / 未观察到”差异。

不要因为差异不显著就声称“此平台不存在侧信道”。该程序不检测漏洞，也不评估系统缓解。
