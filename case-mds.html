First understand the mechanism

Trigger
Faulting or assisting load
Data / prediction source
Fill / store buffers or load ports
Architectural result
Correct retry result or a fault
Affected transient behavior
Unrelated buffer sample consumed

Let region A normally contain 0x17, while 0x6D from other work passes through an affected buffer. A faulting/assisting load of A may transiently receive 0x6D. A later successful retry still returns 0x17, or a real fault is delivered; the sample is not the architectural result. Keeping A fixed does not keep the sample fixed. RIDL, Fallout and ZombieLoad name related research, not three mutually exclusive structures.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] normal LOAD(A) result = 0x17
[02] other work passes 0x6D through an affected buffer
[03] LOAD(A) encounters a fault or assist
[04] transient possibility: t = 0x6D
[05] architectural: correct retry returns 0x17, or report fault
[06] repeat with A unchanged: sample may change

The A in [03] requests one region; 0x6D in [04] came from other activity. Line [05] states what software can legitimately receive. Keeping A unchanged cannot turn sampling into an exact address-selection primitive.

What is trained or triggered?

No branch training is intrinsic. Identify the buffer subtype, the operation opening the sample window and whether data can be attributed to the victim. An internal assist need not be a software-visible exception.

Prerequisites and trust boundary

Relevant conditions include affected Intel hardware, scheduling on a shared core and sometimes SMT sharing. Sampling and postprocessing are different from directly addressing a secret. Report raw sample rate separately from useful secret-recovery rate.

What does the mitigation interrupt?

Supported microcode and kernel buffer-clearing paths work together; evaluate SMT isolation where simultaneous untrusted execution crosses the security boundary. L1D flushing and clearing these buffers are not interchangeable operations.

Do not confuse these concepts

MDS describes the observer sampling a value. LVI describes a victim consuming a wrong operand. SSB can expose an old value from the same logical location, rather than MDS’s unrelated sample.

How to read the original material

In RIDL and the MDS taxonomy, mark the requested address, buffer contents and observed value with different symbols. Ask which subtype supports the claimed sharing boundary before interpreting the result.
