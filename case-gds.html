First understand the mechanism

Trigger
Transient gather encounters a fault
Data / prediction source
Stale vector-related state
Architectural result
Apply gather completion/fault rules
Affected transient behavior
A lane may receive stale value 99

A conceptual gather should assemble [11,22,33,44] from several memory locations. Under an affected transient fault condition a dependent operation may instead see a stale lane value illustrated as 99. This 99 is not the corresponding memory element. Some gather forms can preserve legitimately completed elements on a fault; that architectural partial-completion behavior must not be confused with committing a wrongly forwarded old value.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] intended gather result = [11,22,33,44]
[02] a lane does not complete normally
[03] transient dependent use may see stale 99
[04] 99 came from prior vector-related state
[05] architectural: follow instruction fault/completion rules
[06] do not treat 99 as a legitimate completed element

Compare the intended elements in [01] with the old 99 in [03]. A legitimate completed lane in [05] is not this stale sample. The diagram omits real masking and fault-handling details to isolate that distinction.

What is trained or triggered?

No branch training is intrinsic. The observer’s gather is relevant to the sampling path, while the victim need not execute gather. The input address list does not select which old register content will be inferred.

Prerequisites and trust boundary

Affected Intel models and microcode determine applicability. Vector-state sampling can cross relevant user/kernel, VM and SGX boundaries under documented conditions, including applicable same-core sharing. Identify the concrete context and schedule rather than generalizing from an instruction name.

What does the mitigation interrupt?

Use applicable GDS microcode mitigation and keep lower-privilege contexts from disabling the protection. Linux also documents an AVX-disabling fallback when required microcode is unavailable, with functionality and performance costs.

Do not confuse these concepts

GDS concerns a gather-related sampling path. RFDS concerns other stale register-file states. Neither means the victim must run the observer’s trigger instruction.

How to read the original material
