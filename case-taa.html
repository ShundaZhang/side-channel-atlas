TAA · TSX Asynchronous Abort

Transaction rollback can preserve architectural correctness while a pending abort opens a buffer-sampling window.

First understand the mechanism

Trigger
TSX asynchronous abort pending
Data / prediction source
Internal buffer sample
Architectural result
Abort transaction; roll back its writes
Affected transient behavior
Load consumes an unrelated sample

Start with an architectural counter of 5. A transaction tentatively writes 6, then an asynchronous abort becomes pending. In the affected window a load may consume an unrelated buffer sample, illustrated as 0x42. After rollback the counter is still 5. The tentative write 6, sample 0x42 and committed 5 have three different roles. Atomic rollback of the first does not establish that every microarchitectural trace of the second disappeared.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] committed counter = 5
[02] transaction tentatively writes counter = 6
[03] event: asynchronous abort pending
[04] transient load may consume sample 0x42
[05] architectural: abort; counter remains 5
[06] sample 0x42 is not a committed transaction result

The tentative counter value in [02], unrelated sample in [04] and committed value in [05] are deliberately different. Rolling back 6 establishes transaction semantics; it does not prove that the sample left no observable effect.

What is trained or triggered?

No branch training is central. The sampling side uses a relevant enabled TSX path on affected hardware. The victim need not execute TSX. Neither the transaction address nor the counter selects the secret sample.

Prerequisites and trust boundary

Host or guest applications may be relevant depending on affected hardware and core sharing. Like MDS, useful recovery requires samples plus attribution/postprocessing; it is not a chosen-address memory read.

What does the mitigation interrupt?

Follow platform guidance for disabling affected TSX use or applying applicable microcode and buffer clearing, with SMT isolation where needed. MDS_NO alone is not an adequate TAA conclusion; verify the TAA-specific status and relevant controls.

Do not confuse these concepts

MDS and TAA can involve similar data sources, but the pending transaction-abort window distinguishes TAA. A victim’s lack of transactions does not eliminate this sampling path.
