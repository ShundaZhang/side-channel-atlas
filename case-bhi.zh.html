BHI · Branch History Injection

分支历史上下文变化，可能改变选中的已学习预测目标，而真实目标不变。

前置概念：先分清这些东西

以下以 x86 控制流为例。预测结构不是架构数据存储，“训练”也不是机器学习训练。

直接、间接、条件分支：回答的是不同问题

直接分支把目的地编码在指令中，通常采用相对 PC 的位移。间接分支从寄存器或内存操作数取得正式目标，例如 call rax、jmp [slot]、回调和虚函数调用。条件分支预测回答“跳不跳”，间接目标预测回答“跳到哪里”，两者不是同一个问题。以下 x86-64 示例 call rax 是“调用 RAX 中保存的地址”，不是调用这条指令自身所在的地址。

真实目标、预测目标与 gadget

真实目标由程序操作数和 ISA 规则决定；预测目标让前端能在操作数未就绪时先取指。两者不一致时，错误路径指令被取消，但与数据相关的缓存效应可能保留。gadget 是可在瞬态执行时产生这类可观察效应的现有代码；仅仅跳错目标，还不能证明发生信息泄露。

BTB / 目标预测状态

BTB 即 Branch Target Buffer（分支目标缓冲区）。教学上可把目标预测状态理解为“分支上下文 → 可能的代码目标”的关联。别名 / 碰撞指不同分支源地址或上下文，在预测器有限的索引 / 标签逻辑中重合，不要求完整虚拟地址相同。现代预测器包含多种结构和选择规则；下文只是逻辑模型，不是声称每个 CPU 都只有一张 PC→目标表。

BHB / 历史是上下文，不是函数指针

BHB（Branch History Buffer，分支历史缓冲区）记录用于预测的近期控制流信息。具体记录和压缩方式依实现而异；下文 H_A、H_G 是上下文标签，不是软件可直接写入“BHB 寄存器”的比特串。执行分支会改变历史，历史可改变选中的已学习目标项，但不会改写函数指针，也不会改变比较表达式的真实结果。

这里的“训练数据”是执行过的分支事件

这里不是把秘密字节文件交给机器学习模型训练，而是让软件实际执行控制流：分支源 PC、观察到的目的地、分支类型、近期历史和预测域等因素参与其中。重复执行可建立预测关联，但不是随便重复跳转就能训练指定的受害者分支；是否迁移取决于匹配 / 别名、CPU 行为、屏障、域限制和调度。秘密数据由后面的泄漏 gadget 消费，不是训练标签。

在受害者分支 J 处，函数指针 fp 决定真实目标 NORMAL。概念上的目标预测还会参考近期分支历史及允许域内的已学习目标状态。先在相关预测域内建立有用的 G 关联，再通过实际执行分支构造历史，使目标选择可能偏向 G。两个阶段都不改写 fp。真实目标解析后，CPU 执行 NORMAL 并取消 G 路径。H_A / H_G 是上下文标签，不是软件可写入 BHB 的比特串。

训练 / 输入到底是什么

重点是历史 / 上下文影响目标选择，不是越界数组索引，也不必描述成直接插入一个新的受害者目标。这是因果关注点的区别，不是声称所有 CPU 都有相同的两张硬件表。

概念回看：间接分支 · BTB · BHB · 训练

先明确受害者的间接分支

例如 fp = handlers[id]，然后在位置 J 执行 call fp。当前 id 与 handlers 表共同决定真实目标 NORMAL；fp 未就绪时，目标预测却可能先选 G。改变此前的分支历史，不会改变 id、handlers 或 fp。“候选目标”是预测机制内已学习的目标关联，不是程序里某个 if 的真假条件。

两个不同的准备：建立目标关联，再构造历史

首先，相关预测域内必须存在有用的目标关联。原内核演示借助在内核执行的 eBPF 提供泄漏 gadget，并建立相关预测状态；一般来说，需要合适的同域分支 / gadget 路径，后续研究也找到了不依赖 eBPF 的路径。其次，攻击者在进入受害者域前执行一段分支序列，改变近期历史。这两个阶段影响不同的逻辑输入：前者建立已学习目标状态，后者影响选目标时使用的历史。

“历史选择候选目标”具体是什么意思

用概念式 Predict(J, H, mode, learned_state) 表示目标预测。保持 J、真实 fp 和已学习状态不变，H_A 可能选 NORMAL，而匹配的 H_G 可能选中已学习的 G 关联。真实预测器可能使用折叠历史、标签、多张表及置信度；该式不是固定的“两张硬件表”，更不是任意历史可选任意 G 的保证。调用、域切换及中间分支，也会影响最终到达 J 的实际历史。

为什么 eIBRS 不等于历史隔离

在受影响的 eIBRS 场景中，较低特权预测模式学习的目标受到限制，不能直接用来供应高特权预测；但历史仍可能包含较低特权分支活动。BHI 借这部分影响，选中属于受害者允许预测域的目标项，而不是简单地把任意用户态目标穿过 eIBRS 塞进内核。应区分跨模式的 BHI 与范围更大的同模式 BTI。

训练输入不是什么

关键输入是执行过的分支及其上下文，不是秘密、新函数指针或越界索引。重放匹配历史可使选择偏向某个目标，但不会赋予 G 执行权限，也不会改变真实调用目标。仍须有可用 gadget 和接收通道。入口历史清理序列或适用的 BHI_DIS_S 控制切断历史影响；目标 / 域防护与 gadget 加固则切断链条中的其他环节。

CPU 为什么要参考分支历史？

// C 教学示例：间接调用位置 J 始终相同
void (*fp)(void) = (type == 0) ? func_A : func_B;
fp();  // J：此前的控制流可能与本次目标有关联

同一调用点在 A、B 间切换时，仅按 PC 记住上次目标的预测器容易失准。fp 未就绪前，近期路径上下文可能帮助预测。这只是性能动机，不要求编译器一定生成某种分支序列；优化器也可能使用条件移动或改写代码。

真实历史：不只有 Taken / Not Taken

更一般的概念式是 H_next = F(H_old, 源 PC, 目标 PC, 结果, 类型)，具体实现不一定使用全部输入。BHI 论文介绍过早期 Intel 逆向研究中混入折叠源 / 目标地址信息的历史结构。因此两条全部 Taken 的路径，也可能产生不同上下文。上面的 8 位规则不是 Intel / Arm 的 BHB 公式。真正相关的是到达受害者 J 时的历史；域切换、分发器和中间工作中的分支都可能改变它。

改变已存目标，还是改变查找上下文？

双项逻辑模型。H_A / H_G 是标签，不是真实 CPU 历史；两种模式的真实函数指针都保持 NORMAL。控件用于选择对照实验，不是硬件设置。

必须完整复制受害者的分支历史吗？

不要求通用的“完整历史相等”。不同分支 PC 和历史，可能在有限的预测器索引 / 标签或选择逻辑中发生别名。因此，即使 J 从未正式调用过 G，受害者域内另一条分支学习的目标项也可能产生影响。仅让教学哈希相同不能证明可利用；仍需考虑相关标签、域资格、预测器选择、置信度和可用 gadget。Arm 白皮书 Figure 3 展示的就是这类受害者目标项的别名复用。

“BTI 偏向改变值，BHI 偏向改变查找上下文”可以帮助记忆，但不是严格的硬件分类定理。目标学习、历史与预测器选择相互影响；BHI 是实现 BTI 的一种方式，不是完全互斥的类别。

BTIRSB / Retbleed

成立前提与信任边界

仍需泄漏 gadget 和观察通道。跨域与同模式场景约束不同，需阅读具体内核路径与 CPU 行为；笼统地说已启用 eIBRS，不能解决所有历史相关问题。

缓解切断了哪一环

使用当前平台适用的历史控制、内核历史清理 / 加固及预测器防护组合。Intel 指南区分 BHI_DIS_S，以及在支持平台上用于额外历史加固的 IBHF。应核对适用性，不依赖一个功能标签。

容易混淆的概念

经典 BTI 关注受影响的目标预测，BHI 强调选目标时使用的历史。两者同属 Spectre-V2 家族，都仍需可用泄漏路径。
