Retbleed · Return Target Prediction

即使保存的正式返回地址未被改写，RET 仍可能短暂走向错误预测目标。

触发事件
RET 处于受影响预测条件
数据 / 预测来源
返回目标预测状态
正式结果
正式返回保存的 R_OK
受影响的瞬态行为
短暂执行 R_OTHER

CALL worker 保存返回地址 R_OK。在 RET 的真实结果确定前，CPU 可能先从预测目标取指。Retbleed 展示特定 Intel 与 AMD 实现上的受影响返回预测路径。模型中的 R_OTHER 是错误目标标签，不会替换保存的返回地址。返回解析后，错误路径被取消，但已经执行的泄漏 gadget 仍可能留下痕迹。

语义伪代码 / 不是可执行 PoC

01  CALL worker  // saved return = R_OK  // 抽象的调用 / 返回上下文
02  worker: saved_return remains R_OK  // 没有改写软件栈上的返回地址
03  RET  // 返回指令自身就是分支
04  affected_predict(RET) = R_OTHER  // 并非通用的 RSB 下溢规则
05  transient: execute(R_OTHER)  // 错误路径 gadget 可能留下痕迹
06  architectural: return_to(R_OK)  // 真实返回目标解析后仍被遵守

编号语义伪代码，不是可运行攻击。标签和数值均为教学设定，不配置预测器、不制造故障，也不解码秘密。图是概念模型，不是实测时序。
[01] CALL worker，保存返回地址 R_OK
[02] worker 执行，保存地址仍为 R_OK
[03] RET
[04] 受影响预测：目标为 R_OTHER
[05] 瞬态：R_OTHER 的指令可能先执行
[06] 正式：返回 R_OK

[01] 保存的地址在 [02]、[06] 中都不变，变化的是 [04] 的提前预测，因此不能把模型读成栈破坏或软件返回地址攻击。

训练 / 输入到底是什么

相关状态是返回 / 目标预测。研究涉及的 Intel 设计中 RSB 下溢很重要，但同一规则不能概括文献描述的 AMD 行为。不能把某一实现的触发条件当作所有 RET 的通用规则。

成立前提与信任边界

需要可触达的返回点、合适的受害者代码及研究中的预测器共享条件。内核泄漏演示不能外推为更新或不同配置 CPU 上的相同行为。

缓解切断了哪一环

按型号使用微码和内核返回路径缓解，包括适用的返回跳板、RSB 处理或硬件控制。retpoline 使用返回指令，不等于在返回本身进入受影响预测路径时仍能单独保护。

容易混淆的概念

预测问题不是栈覆盖，也不是用 ROP 改写正式返回地址。BHI 关注历史选择，Retbleed 关注返回指令进入哪种预测路径。
