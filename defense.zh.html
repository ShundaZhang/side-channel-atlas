04 / DEFENSE & SOURCES

缓解在多层，
结论也要分层

软件 gadget、编译器、内核、微码、固件、隔离与调度各能处理不同环节。先确认信任边界和机器状态，再决定优先级。

01 / DEFENSE IN DEPTH

每层解决不同的问题

没有一条通用开关能消除所有侧信道。缓解也可能带来性能成本，必须依据实际威胁模型评估。

SOURCE / COMPILER

削弱可利用 gadget

在敏感访问上采用经过审查的常数时间实现；对具体预测型 gadget 使用合适的索引约束、屏障或编译器加固。普通边界检查不能保证瞬态安全。

KERNEL / RUNTIME

隔离与入口路径

内核和运行时可能采用 KPTI、retpoline、IBRS/IBPB、STIBP、SSBD、BHI 专项缓解等；它们适用的攻击类别和跨域边界不同。

MICROCODE / PLATFORM

处理器特定缓解

MDS/GDS 缓冲区清理、预测器控制、硬件修订等需按厂商公告与固件版本核对；虚拟机还依赖宿主层。

“启用缓解”是对特定问题、型号和信任边界的声明。不要把某个系统状态字符串读成“整个 CPU 不再有侧信道”。

把缓解措施对应到硬件结构

措施改变什么验证点
常数时间设计与推测加固去掉依赖秘密的分支和访存地址。对敏感 gadget，使用受支持的屏障或约束索引的数据依赖。检查优化后的机器码并测试计时类别，核实加固在目标 CPU 上的语义。
IBRS · IBPB · STIBPIBRS 限制间接预测；IBPB 隔断边界前后的预测影响；STIBP 限制 SMT 兄弟线程的影响。核对 CPU 能力与 OS／虚拟机监控器实际应用措施的时点。返回预测和分支历史可能需要额外措施。
MD_CLEAR · L1D flush受支持硬件上的缓冲区清理针对内部数据采样；L1D 刷新针对一级数据缓存内容。核对涉及结构及出入边界。切换时清理无法消除并发共享。
CAT / resctrl硬件支持时，缓存分配类别可限制各工作负载分配到哪些缓存路。检查掩码是否重叠、缓存域和共享映射。限制分配路不能保证消除共享行观测或其他结构的通道。

02 / REVIEW CARD

一页审查清单

用于系统设计评审、密码实现审查或云上部署盘点；结论应记录证据来源和日期。

THREAT

谁与谁共享资源？

不可信本地代码、浏览器脚本、同核 SMT 线程、其他 VM、宿主、TEE 外部代码，各自权限和共享条件是什么？

SECRET

秘密在哪里？

密钥、会话材料、受保护页面、寄存器、内部缓冲区。关键操作是否依赖秘密改变访问模式或时长？

MACHINE

当前机器是什么状态？

记录 CPU 型号/stepping、微码、BIOS、内核、虚拟化层、SMT、编译器及缓解状态，不只记一串 CVE。

EVIDENCE

证据到哪一级？

理论可能、实验室 PoC、受影响产品公告、系统缓解显示、生产监控事件，彼此不能替代。

CHANGE

更新会改变什么？

升级 CPU 微码和 OS；检查性能与兼容性；重新读取官方公告和系统状态，再定期复核。

RESIDUAL

剩余风险是什么？

软件定时泄漏、未覆盖的新变体、TEE 共享微架构状态、宿主不可见缓解与多租户调度。

03 / READ-ONLY CHECK

在 Linux 上先读状态

以下命令只读取内核公开的漏洞状态，不修改缓解设置。不同发行版和虚拟环境的输出可能不同。

uname -a grep -m1 -E 'model name|Hardware' /proc/cpuinfo for file in /sys/devices/system/cpu/vulnerabilities/*; do printf '%s: ' "${file##*/}" cat "$file" done
在 VM 内看到 “Not affected” 或 “Mitigation” 也要考虑宿主 CPU、超管暴露的特性与供应商公告。若输出 “Unknown”，不要按“安全”解释。参见 Linux 硬件漏洞索引 ↗。
04 / TRUSTED EXECUTION

TEE 也运行在真实 CPU 上

加密和隔离保护的是定义好的接口与架构边界；它们不会自动消除所有共享微架构状态。

SGX

Foreshadow 与 SGXSpectre

两类研究分别展示 L1TF 和预测型 gadget 对 enclave 的不同威胁。读论文时分清 SGX 密钥 / 页内容与实验演示的泄漏目标。
