02 / CASE FILES

Nine cases worth studying closely

Filtering mechanism, then open papers, announcements and original author PoC. PoC links point to source code or research pages, not execution buttons on this site.

2018 · PREDICTION · CVE-2017-5753

Spectre V1 · Bounds Check Bypass

Wrong prediction boundary check, allowing the victim code in the same address space to transiently access out-of-bounds data and then observe it through the cache channel. The key lies in the specific gadget and controllable input, not "any machine code can exceed authority".

Reproduction premise:Target compilation results, training window, measurement environment and protection will all affect the demonstration.

Separate the window and the channel. Delaying the bounds operand can give wrong-path loads time to execute. A second load indexed by the transient value converts the first load’s data into a measurable line. A mitigation must stop or constrain the relevant dependent access.

2018 · PREDICTION · CVE-2017-5715

Spectre V2 · Branch Target Injection

The attacker affects indirect branch target prediction, and the victim transiently executes code fragments with leakage capabilities. Read defense distinguishes between users/kernels, processes, and virtual machine boundaries.

Reproduction premise:Predictors and mitigation mechanisms are highly dependent on CPU, microcode and system version.

Identify the indirect branch, the predicted target and the disclosure gadget separately. The architecturally resolved target can remain correct while a different gadget runs transiently. Kernel entry, guest entry and SMT sharing require different predictor controls.

Original paper ↗Linux Mitigation Documentation ↗
2018 · FAULT · CVE-2017-5754

Meltdown V3 · Rogue Data Cache Load

On some affected processors, protected data may be used by transient chains until the permission failure is handled. Unlike the Spectre mechanism that trains the victim branch, KPTI is one of the historically important operating system countermeasures.

Reproduction premise:Old hardware and old configurations; PoC failures on updated hosts are common.

On affected hardware, a supervisor-only load can make its value available transiently before a fault takes effect architecturally. KPTI removes most kernel mappings from the userspace page-table view, changing which addresses are reachable by this mechanism.

Original paper ↗Research PoC ↗
2018 · FAULT · L1TF

Foreshadow / L1 Terminal Fault

Faults triggered by termination page table entries interact with L1D data, which can affect SGX, system management, and virtualization boundaries. Different scenarios correspond to different CVEs; don’t just use “L1TF” to infer target environment risks.

Reproduction premise:Processor, page table scenario, host/guest configuration.

A terminal-fault PTE can transiently contribute physical-address bits. The affected lookup is constrained to data already resident in L1D. This explains why PTE sanitization and L1D flushing at relevant VM transitions target different parts of the chain.

2019 · SAMPLING · MDS

RIDL / ZombieLoad / Fallout

Sampling old data from the fill buffer, load port, or store buffer. Unlike original Meltdown, the attacker usually cannot specify an arbitrary target address; co-core, SMT and post-processing are critical.

Reproduction premise:Specific Intel CPU, buffer behavior, microcode and kernel state.

Use the structure names to distinguish variants. Fill buffers track outstanding line fills; store buffers hold pending writes; load ports handle load data. A raw sample may contain data from unrelated activity, so recovery rate and the ability to attribute data to a victim are separate measurements.

Research Overview ↗Original author PoC ↗Linux Documentation ↗
2022 · PREDICTION · BHI

Branch History Injection

Branch history can affect subsequent indirect target selection, even if there is some cross-privilege predictor isolation. The analysis depends on the specific victim gadget, kernel build, and subsequent mitigation.

Reproduction premise:Model, system version and triggerable code path.

BHI is a way to influence indirect target selection through history. Read how the target CPU combines branch history with target prediction and where the kernel scrubs or restricts that history. This is a control-flow steering technique; a usable disclosure gadget and receiver are still required.

Intel Technical Guide ↗Linux Documentation ↗
2023 · SAMPLING · CVE-2022-40982

Downfall / Gather Data Sampling

On some Intel processors, transient gather can sample previous vector data. It is a data sampling problem and does not mean that the target program must call gather.

Reproduction premise:Affected models, microcode, vector instructions and same-core/same-thread conditions.

Gather combines data from multiple memory locations into vector lanes. The attacker’s transient gather on affected hardware can obtain stale vector data from earlier activity; the relevant evidence is the sampling behavior and vector-use boundary, including sibling threads where applicable.

Original paper ↗Original author PoC ↗Linux Documentation ↗
2023 · PREDICTION · CVE-2023-20569

Inception / SRSO

Return address prediction is manipulated, potentially leading execution to transient leak fragments. AMD's announcement emphasizes differences in utilization conditions and product generations; mitigation involves microcode and operating system configuration.

Reproduction premise:Affected AMD models and correct return prediction conditions.

The Inception paper separates Phantom speculation from training in transient execution: predicted control-flow effects can seed a subsequent return misprediction. Read the CPU-specific mitigation path before assuming generic branch-history clearing covers return prediction.

2023 · REGISTER LEAK · CVE-2023-20593

Zenbleed · cross-process register remnants

Zen 2 Under certain microarchitecture conditions, the YMM register may retain other process/thread sensitive information. It is different from the classic Spectre chain of "train branch → cache encoding" and is suitable as a classification edge case.

Reproduction premise:Zen 2. Specific command conditions and repair status.

On affected Zen 2 cores, the original report connects speculative VZEROUPPER and recovery to physical vector-register lifetime. VZEROUPPER logically clears the high halves; incorrect recovery can make stale register-file contents architecturally readable. This case does not need a cache timing receiver for the disclosed register contents.

03 / HOW TO READ

When reading a new advisory, look beyond the CVE

Record in this order: Triggering conditions → Data sources → Trust boundaries → Actual attacker capabilities → Official mitigations → Residual conditions.

EVIDENCE

Research PoC

Answer "whether it is observable under certain conditions". Its performance, success rate, and target devices cannot be automatically extrapolated to all platforms.

APPLICABILITY

Vendor advisory

Identification of affected products and supported microcode/firmware. The same vulnerability name may have different conclusions in different generations.

DEPLOYMENT

System documentation

Confirms the actual enabled mitigation and visibility status of the current kernel. Cloud virtual machines also depend on the host layer.
