Spectre V1 · Bounds Check Bypass

A conditional check eventually fails, but its predicted pass path may already have used an out-of-bounds value.

First understand the mechanism

Trigger
Unresolved conditional branch
Data / prediction source
Victim-accessible array data
Architectural result
Reject x = 16 when size = 16
Affected transient behavior
Predicted pass; use array1[16]

A byte array starts at teaching address 0x1000 and has 16 elements. Legal indices 0–15 refer to 0x1000–0x100F. Inputs such as 2, 5 and 9 make the same check pass. If x is then 16 while the comparison is unresolved, prediction can temporarily enter the check’s body. The real comparison still rejects it. Only a data-dependent, observable side effect makes this a disclosure path.

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] array1_size = 16; x = 16
[02] if x < array1_size:          # condition is not ready yet
[03]     value = array1[x]       # belongs inside the pass path
[04]     observe_placeholder(value)
[05] transient possibility: predicted pass reaches [03]–[04]
[06] architectural result: condition is false; discard that path

Read [02] as the gate for both [03] and [04]. Line [05] describes a possible early path, not a change to the Boolean result. In [06], 16 is still rejected. A short speculative window or unusable channel can prevent disclosure despite a misprediction.

What is trained or triggered?

Legal inputs bias branch-outcome history. The predictor does not memorize a list of permitted indices or evaluate x < 16 itself. Source-level “pass” need not mean a taken machine branch; compilation can invert the branch direction.

Prerequisites and trust boundary

The attacker needs an influenceable input, a reachable victim gadget and an observable channel. The basic example crosses a software object or sandbox check within the victim’s accessible address space; it does not make a forbidden kernel page architecturally readable.

What does the mitigation interrupt?

Harden the relevant dependency and speculation boundary with platform-appropriate barriers, index handling or compiler transformations. Review the generated code and the particular check. A system-wide Spectre-V1 status is not a proof that every application gadget is hardened.

Do not confuse these concepts

V1 predicts a direction. V2 predicts an indirect target. Neither example requires the load-permission failure central to classic Meltdown.
