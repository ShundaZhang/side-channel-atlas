BHI · Branch History Injection

Changing branch-history context can change which learned target is predicted, without changing the real target.

First understand the mechanism

Architectural result

Affected transient behavior
A history-selected wrong gadget

Hold the indirect branch J, real target NORMAL and learned candidates A/B constant. In a conceptual predictor, context H_A selects A while H_B selects B. If B is wrong, its instructions may briefly execute before resolution. H_A and H_B are labels, not recipes for real history construction. This contrast illustrates why restricting target state and isolating history are not necessarily the same intervention.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] indirect branch J; real target = NORMAL
[02] learned candidates A and B stay fixed
[03] context H_A → prediction A
[04] context H_B → prediction B
[05] transient: if B != NORMAL, B may execute
[06] architectural: execute NORMAL, not B

Between [03] and [04], hold [01] and [02] fixed. Only the history context changes. The example isolates a selection effect without claiming a particular hardware table layout or a recipe for generating H_B.

What is trained or triggered?

The emphasis is on history/context influencing target choice, not an out-of-bounds array index. It need not be described as directly inserting a fresh victim target. This is a distinction in causal focus, not a universal two-table microarchitecture.

Prerequisites and trust boundary

A leakage gadget and an observation channel remain necessary. Cross-domain and intra-mode cases have different constraints. Read the exact kernel paths and CPU behavior; a broad statement that eIBRS is enabled does not settle every history-related attack.

What does the mitigation interrupt?

Apply the current platform-specific combination of history controls, kernel history-clearing/hardening and relevant predictor protections. Intel guidance distinguishes BHI_DIS_S and, on supporting systems, IBHF for additional history-related hardening. Verify applicability rather than relying on a single feature label.

Do not confuse these concepts

Classic BTI focuses on influenced target prediction; BHI highlights the history used to choose a target. Both belong to the Spectre-V2 family and still require a useful disclosure path.

How to read the original material

In the BHI paper, label branch PC, history and target candidates separately. In updated vendor guidance, distinguish the original attack class from later gadgets and hardening additions.
