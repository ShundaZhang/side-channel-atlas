2018 / CVE-2018-3639

SSB · Spectre V4

A later load may temporarily read OLD before an earlier overlapping store’s address is resolved.

First understand the mechanism

Trigger
Unresolved earlier store address
Data / prediction source
Old value of the same location
Architectural result
Respect store → load dependency
Affected transient behavior
Load bypasses store and sees OLD

Set slot_A to 3, then execute *p = 8 followed by v = *q, with p and q ultimately naming slot_A. While p’s address is unresolved, a memory-dependence predictor can guess that the two accesses do not overlap. The load may then consume 3. Once the overlap is discovered, recovery must obtain 8. If p truly names another location, reading 3 from slot_A is correct, so address equality is essential to the example.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] slot_A = 3
[02] STORE(p, 8)           # earlier, address not ready
[03] v = LOAD(q)           # q names slot_A
[04] predict no overlap → transient v = 3
[05] resolve: p and q both name slot_A
[06] architectural: recover/re-execute; v = 8

Line [05] makes the aliasing relation explicit. Without that overlap, reading 3 is not an error. The difference between [04] and [06] is the value of the same location, not a sample from unrelated work.

What is trained or triggered?

This is memory-dependence prediction, not V1’s conditional direction or V2’s target prediction. Branch training is not a defining prerequisite. Implementation-specific history may matter, but the causal question is whether the later load wrongly bypassed a conflicting earlier store.

Prerequisites and trust boundary

A disclosure requires victim code that makes the stale value security-sensitive, such as an old pointer before an intended overwrite. A timing difference in two ordinary loads does not by itself demonstrate sandbox escape or key disclosure.

What does the mitigation interrupt?

Use applicable Speculative Store Bypass Disable (SSBD) controls and platform/compiler guidance at the relevant boundary. Costs and enablement depend on CPU and workload. Disabling unrelated branch prediction is not an explanation of this dependency fix.

Do not confuse these concepts

The stale 3 belongs to slot_A. MDS’s illustrative 0x6D came from unrelated buffer activity; the two meanings of “old data” must not be merged.

How to read the original material

In the vendor example, find the earlier overwrite, the later dereference and the dependency that the predictor misses. Keep instruction order separate from the order in which addresses become available.
