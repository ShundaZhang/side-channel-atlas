RFDS · Register File Data Sampling

Previously used register-file values may be sampled; this is not reading another task’s current named register.

First understand the mechanism

Sample may reflect OLD

A prior context used value OLD. The current context’s legitimate operation uses CURRENT. An old physical register-file entry can retain OLD until overwritten. In an affected condition a sample may reflect OLD, even though normal register operations must still follow the current context’s architectural state. OLD is a data label, not a register number to request. The model intentionally does not invent a universal RFDS trigger instruction.

Follow the teaching example

Numbered semantic pseudocode, not a runnable attack. Labels and values are illustrative; it does not configure predictors, manufacture faults or decode secrets. The diagram is conceptual, not a measured timing trace.
[01] prior context used OLD
[02] current context legitimately uses CURRENT
[03] an old register-file entry may still retain OLD
[04] affected sampling may reflect OLD
[05] normal architectural operations still use CURRENT
[06] clearing targets affected stale entries

OLD in [03] is an internal retained value, not a register name the observer may choose. CURRENT in [05] remains the current context’s valid state. The example explains provenance rather than inventing a trigger instruction.

What is trained or triggered?

No branch training is central. The stale source can involve integer, floating-point or vector values depending on the affected core. Sampling does not let the observer choose the exact disclosed value.

Prerequisites and trust boundary

RFDS applies to particular Intel Atom/E-core implementations, not every E-core. Documented affected cores lack SMT; the boundary concerns prior use of the same affected logical processor, including process or guest transitions. Do not import a cross-SMT model from GDS or MDS.

What does the mitigation interrupt?

Applicable microcode enables RFDS clearing through VERW. Kernel/KVM paths clear at relevant user-return and VM-entry boundaries. Check the RFDS-specific enumeration and status; sharing a mitigation instruction with MDS does not make the vulnerabilities identical.

Do not confuse these concepts

RFDS is not another name for GDS, and “stale register value” does not imply an architectural permission to read another task’s register file.

How to read the original material

Use the RFDS disclosure’s distinction between current architectural values and old entries. Verify the exact core type and RFDS_CLEAR/RFDS_NO support rather than identifying a CPU only by its marketing family.
