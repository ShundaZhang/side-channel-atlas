01 / COMMIT

架构状态不等于 CPU 的全部状态

程序员能从 ISA 观察到的寄存器、内存、异常和控制流属于架构状态。乱序核还维护缓存、分支预测器、重排序缓冲区（ROB）、载入 / 存储队列等。错误预测发现后，尚未提交的指令结果会被丢弃；但执行过程中加载的缓存行等痕迹，未必自动恢复到此前状态。

所以“未提交”不意味着“未执行”。这个差别是理解瞬态执行攻击的起点，也是Intel 术语文档区分 disclosure gadget 与通道的背景。

架构上

错误路径的寄存器写入和异常处理结果不会像普通已提交指令一样对程序可见。

微架构上

缓存、预测器或临时缓冲区可能已经变化；攻击者随后从耗时差异间接观察。

乱序核心内部有哪些结构

ISA 规定软件可见的契约，包括指令、寄存器、异常规则、特权级和内存顺序。微架构是这个契约的一种具体实现。两个处理器可以运行同一个二进制，但缓存组织、预测器、吞吐量、计时和推测行为各不相同。内部执行顺序可以变化，提交结果仍受架构规则约束。

结构作用可观察现象
分支预测器方向、目标与返回预测让前端持续取指。预测错误的耗时，以及对瞬态控制流的影响。
ROB / rename / scheduler跟踪在途操作、依赖和精确提交。队列与执行端口竞争；残留状态泄漏依赖特定漏洞。
Load/store queues · fill buffers跟踪访存顺序、存储转发与缓存行填充。依赖加载的耗时，以及特定型号的转发或采样行为。
TLB · page walker缓存地址翻译；未命中时遍历页表。地址翻译竞争、页表遍历带来的额外延迟。
Caches · prefetchers · coherence缓存数据行、预测后续访问，并协调不同核心上的副本。缓存行驻留、组竞争、预取误报与远端缓存命中。
互连、内存与功耗控制转发请求、调度 DRAM，并调节电压和频率。带宽竞争、DRAM 行缓冲效应和频率引起的计时差异。

02 / OBSERVATION

侧信道是统计推断，不是“直接读内存”

观察者不能通过正常接口读取秘密，却能看见受秘密影响的现象：执行时间、缓存竞争、功耗、频率、端口占用或内存访问模式。侧信道通常强调从受害者活动推断信息；隐蔽信道通常强调发送端主动把数据编码进非预期共享资源。瞬态执行攻击中，攻击者可能诱导受害者瞬态编码秘密，再自行接收。

实际测量不是“一次命中 60 周期、未命中 200 周期”这样固定。核心频率、预取器、中断、迁核、计时器精度和竞争任务都会使分布重叠。读论文时应找样本数、成功率、带宽、误报率及硬件配置，而不只看演示视频。

secret → shared microarchitectural state → timing distribution → inference
计时侧信道、缓存侧信道、电力/频率侧信道并不都依赖瞬态执行；反过来，瞬态执行也需要一个可观测的泄漏通道才能形成信息泄露。

03 / CACHE PRIMITIVES

两种缓存痕迹探测方法

缓存按行传输数据。在传统组相联缓存中，地址先映射到一组，再用 tag 在该组 W 个 way 里识别缓存行。对简单的二次幂缓存，低 log₂(行大小) 位是行内偏移，接下来 log₂(组数) 位选组，其余高位构成 tag。真实 LLC 还可能对物理地址位做哈希来选 slice 或 bank；仅看虚拟地址通常无法知道这些位。

Flush+Reload

观察同一物理缓存行。重载较快提示该行近期可能被访问。

Prime+Probe

用自有缓存行观察同一组竞争。探测较慢提示已有行可能被替换。

Flush+Reload

选择一个双方映射到同一物理行的地址，例如共享文件映射中的只读代码。双方虚拟地址可以不同；写时复制生成私有页后，这个共享关系就断了。在适用的 x86 平台，CLFLUSH 可使一致性域中的目标行失效。应核对指令支持、排序、映射及实际跨核行为。

每个窗口：
    逐出 L，并保证逐出先于观测窗口
    等待一个观测间隔
    dt = 计时第一次加载 L
    记录(时间戳, dt, dt < 阈值)

先用受控读取者采集“有访问／无访问”基线。预取和无关进程访问会造成误报；重载前被替换、漏掉窗口、测量被延迟会造成漏报。较快的重载可能来自私有缓存、LLC 或核间转发，应看分布再判断，而不是凭一次读数指认缓存层。原论文在其平台条件下验证了共享行探测的高分辨率。

Yarom 与 Falkner · USENIX Security 2014 ↗

Prime+Probe

以 LLC 为例，先选出会在同一 set 和 slice 里竞争的自有地址，并验证访问它们能逐出参考行。攻击者与受害者无需共享同一物理页，但选定层级的缓存必须共享，且受害者访问确实到达或影响这一层。某些设计中，私有缓存命中可能几乎不产生 LLC 信号。

  1. Prime：按验证过的顺序遍历 A。用依赖指针链让后一条加载等前一条返回，减少访存重叠和简单步长预取。
  2. 等待：留出受害者活动的窗口。冲突行可替换某条 A 行，中断处理和其他任务也可能造成同样效果。
  3. Probe：计时整条遍历，或分别计时每条自有行。保持稳定的探测顺序，一次重载本身也可能替换下一条自有行。
  4. 推断：用空闲基线解释慢探测或未命中数。结果指向窗口内发生竞争的一组，该组可对应许多无关地址。
A = 已验证映射到同组、同 slice 的自有缓存行
每个窗口：
    按 prime 顺序遍历 A
    等待一个观测间隔
    dt = 按 probe 顺序计时遍历 A
    记录(时间戳, dt, dt > 阈值)

如何构造逐出集合

从自有候选地址池 S 和参考行 x 开始。相同页内偏移可固定部分组索引位，但物理地址高位与 slice 哈希仍未知。定义逐出判定：先预热 x → 遍历 S → 计时 x。重复测量并与正负对照比较逐出率。缩小后的池仍能稳定逐出 x 才保留，最后跨多轮、不同访问顺序复验。

贪心缩减每次尝试删一个地址。Vila 等提出分组消除：在理想 W 路模型中，把大候选池分成 W+1 组；若选定 W 条同组行就足以逐出 x，则至少有一组不含这 W 条，删除它仍保留逐出能力。测试各组的补集，继续缩减，再验证单个成员。TLB 抖动、实际替换策略及测量噪声都会破坏理想判定的单调性，因此需要报告实测逐出率及不确定性。

Liu 等 · IEEE S&P 2015 ↗ · Vila 等 · 逐出集合构造 ↗ · Mastik ↗

其他探针及其取舍

Evict+Reload 用同组逐出集合代替显式 flush，仍计时目标行。Flush+Flush 计时 flush 指令本身；在研究所用 CPU 上，其耗时与驻留状态有关。NDSS 2025 的对比还在特定处理器上评估了基于缓存行降级的探针。阅读时可逐项核对共享内存前提、快慢方向、时间分辨率和误报率。

04 / TRANSIENT WINDOW

触发瞬态执行的几条路

预测型：训练条件分支、间接分支或返回预测，使处理器暂时沿错误路径执行。Spectre V1 是边界检查绕过；V2 是间接分支目标注入。错路径被撤销，但可留下缓存编码。

故障 / 辅助型：权限检查、页故障或微码辅助完成前，错误值可能进入瞬态依赖链。原始 Meltdown（Variant 3）属于此类。不能假定所有 CPU 都有同样数据转发行为。

数据采样型：特定处理器的内部缓冲区、向量寄存器相关结构可能让过期数据进入瞬态指令。MDS 与 GDS 的对象更像“同核附近的某些数据”，不等同于按任意地址读取。

把 Spectre 与 Meltdown 当作两个历史入口有用，但后续变体不能只靠名字分类；看具体的预测 / 转发机制、越过的边界和厂商受影响清单。Intel 的分类建议也强调这一点。

乱序执行让已就绪操作先发射；推测执行还会在结果或路径尚未确定时先按假设推进。故障触发的瞬态工作可以完全不经过分支误预测。窗口长短受依赖延迟、前端、队列容量以及恢复时机共同限制。延迟分支操作数可能给依赖加载留下时间，但错误路径上的另一次长延迟访存也可能耗尽窗口。

05 / ANATOMY

拆解一次 Spectre V1 的逻辑链

受害者正常会检查索引，再访问数组。攻击者提供输入并影响预测器。若处理器暂时猜“检查通过”，错路径可能读取越界位置；其值若又用作另一块探针数组的索引，就会把某一条缓存行变热。处理器最终发现检查失败，撤销架构结果；攻击者仍可测哪条探针线更快。原始论文中的演示要靠反复训练、测量和降噪，不能把一次计时当作可靠泄漏。

train → mistrain → transient load → encode(value) → squash → time(probe)

这里“越界”指软件对象 / 沙箱边界，不等于任意读取另一个进程或内核地址。V2、Meltdown、MDS 的触发和边界各不相同。对照原始 Spectre 论文和原始 Meltdown 论文阅读。

06 / THREAT MODEL

不要从 PoC 成败直接推断平台安全

  • 攻击者能力：能否运行本地代码、JavaScript、同核线程或恶意 VM？
  • 目标秘密：同进程、跨进程、内核、虚拟机、SGX / TEE，边界不同。
  • 硬件条件：微架构代际、SMT、TSX、缓存共享、预测器隔离会改变效果。
  • 软件条件：微码、内核、浏览器、编译器、虚拟化层和相关开关都要记录。
  • 证据级别：论文概念、受控 PoC、供应商公告、在野利用是不同的主张。
