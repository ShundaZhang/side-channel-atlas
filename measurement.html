01 / ACQUISITION

Acquire a trace you can audit

Record one row per probe: run, timestamp, line or set, latency, known condition (in calibration), CPU identifier and validity reason. Keep raw times. A probe mutates cache state; the capture window, flush/prime order, and the time spent scanning multiple sets define what it can see.

On x86, inspect the processor manual for timer and fence semantics. RDTSCP waits for prior loads but does not by itself block later instructions from starting; fence the measured region as required by the selected timer sequence. TSC deltas are ticks, not necessarily core cycles. Control CPU placement, record topology and migrations, fault in pages and warm up the timer. Use an empty bracket to estimate timer overhead, rather than treating that overhead as constant across environments.

Separate machine effects from event labels. Interleave or randomize positive and negative trials; keep cache reset, placement and window length the same. Use a nearby reference trace to recognize shared interruptions, and a no-target control to estimate false alarms. Randomize address order or use dependent reads where applicable, then test whether prefetch and probe-induced eviction actually decrease.

02 / DECISION RULE

Turn latency into a decision

For Flush+Reload, a short delay supports activity; for Prime+Probe, a long probe supports contention. Use an oriented score s (for example −latency or +latency) so that larger means more evidence. Estimate both conditional distributions from labeled controls. A midpoint of two medians is a rough start; overlapping tails, unequal variance or multiple cache levels can make that choice poor.

Sweep the threshold on calibration data. Each threshold gives a point on the ROC curve: x = FPR = FP/(FP+TN), y = TPR = TP/(TP+FN). Select by an operational limit such as FPR ≤ 1%, or a loss with explicit false-positive and false-negative costs. Freeze the threshold and measure again on holdout runs. Report both rates and coverage if an uncertain band rejects some samples.

The same false alarm rate can dominate a rare-event workload. For an event rate of 1%, TPR 95% and FPR 5%, Bayes’ rule gives precision 0.95·0.01 / (0.95·0.01 + 0.05·0.99) ≈ 16%. Out of 10,000 windows that is about 95 true alerts and 495 false alerts. Test against a realistic base rate and report precision as well.

03 / ROBUST ESTIMATION

Handle spikes, bursts and drift

PatternMethod and rationaleFailure mode
Isolated high delaysSummarize calibration classes by median and IQR/MAD. A few extreme values have limited effect on rank statistics.High latency can also be the Prime+Probe signal. Define censoring from independent quality flags or controls, and report loss.

MAD = median(|xᵢ − median(x)|), IQR = Q₃ − Q₁. These describe scale; 1.4826 × MAD estimates a normal standard deviation only under a normal model. Median filters need a window chosen for the event duration. The toy figure uses a centered filter, which needs a future sample; a live detector must use a trailing window or accept delay.

04 / DECODING

Recover events from repeated or multichannel traces

Voting and likelihood

For the same known-duration event repeated independently, score each aligned observation and combine the evidence. For five independent decisions with single-trial accuracy 0.7, a majority is correct with probability Σ(k=3…5) C(5,k)·0.7ᵏ·0.3⁵⁻ᵏ ≈ 0.837. Common interruptions break the independence assumption. If calibrated scores are available, sum log likelihood ratios log[p(s|event)/p(s|idle)] rather than giving a borderline timing the same weight as a clear hit.

Cache templates

Gruss et al. profile which lines are often active for each known event, then compare new traces with that access matrix. For a teaching decoder, set θ[c,j] = (hits[c,j]+α)/(valid[c,j]+2α), using α > 0 to avoid log(0). With binary line evidence b[j], a simple conditional-independence model adds log(θ[c,j]) for a hit and log(1−θ[c,j]) for a miss, plus the log class prior. Skip erasures only under an appropriate missingness assumption. Select the best score or abstain if the margin is too small.

In the figure, with equal priors and no missing values, (1,1,0,0) has likelihood 0.9·0.8·0.8·0.9 = 0.5184 for A and 0.1·0.2·0.2·0.1 = 0.0004 for B. The ratio is 1296 under this model. Adjacent lines may share prefetch and code paths; treating highly correlated channels as independent makes confidence too high. Choose features on training runs and report top-k accuracy or precision/recall on unseen runs.

Alignment and frequency-domain filtering

When repetitions start at different times, align with a public marker where possible. Alternatively, slide a known waveform template over a bounded lag range and find the largest normalized cross-correlation (Pearson correlation on the overlapping samples). Centering and scaling reduce sensitivity to offset and gain; background rhythms and searching many lags can yield spurious matches. Fix the lag search rule before test runs.

For a periodic target, measure per-set samples at a stable cadence, remove the mean, apply a window and compare power near the expected frequency against idle controls. The public-cloud study uses power spectral density to find candidate sets. Welch’s PSD estimator splits a regular series into overlapping segments, windows them and averages squared FFT magnitudes after normalization. It lowers spectral variance at the cost of frequency resolution. Jitter, aliases and other periodic tasks can create misleading peaks; verify candidates in held-out time traces.

05 / VALIDATION

Distinguish detectable leakage from a useful decoder

For a fixed-vs-random timing check such as dudect, Welch’s t statistic compares means with unequal sample variances. For groups A and B, t = (mean(A)−mean(B))/√(s²_A/n_A+s²_B/n_B). A large |t| under the test assumptions is evidence of a mean difference, not a per-trace decoder, effect size or key-recovery result. Fixed/random groups must be assigned and collected so they do not simply track run order or load. A small |t| does not establish constant time; other distributions, inputs or environments may leak.

Report held-out error rates with denominators and intervals. For independent labeled windows, use a Wilson binomial interval: 5 false positives among 100 negatives gives a 95% interval of about 2.2–11.2%, so it cannot certify a 5% limit. If samples are correlated, use independent repeated runs as replicates or bootstrap whole runs/blocks rather than individual windows. Vary block length and report sensitivity.

Keep the CPU, cache level, mapping and mitigation status alongside the trace. Report window duration, sample count, losses, FPR and FNR, and the number of independent runs. Freeze the detector before the final run. If you scan many sets, lags or time points, validate selected peaks on a separate run or account for multiple comparisons. Distinguish a statistically separable cache state, a reliable event label and a successful end-to-end inference.
